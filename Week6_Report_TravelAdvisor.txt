4. PRODUCTION CODE CHANGES
================================================================================

4.1 render.yaml

The Render Blueprint file was updated to define the deployment configuration:

  services:
    - type: web
      name: traveladvisor-api
      runtime: node
      plan: free
      buildCommand: npm install && npm run build && cd backend && npm install
      startCommand: cd backend && node server.js
      healthCheckPath: /

Build sequence explained:
  Step 1: npm install           — Install root React dependencies
  Step 2: npm run build         — Compile React app to /build
  Step 3: cd backend            — Move to backend directory
  Step 4: npm install           — Install Express dependencies
  Step 5: node server.js        — Start Express (serves API + React build)

4.2 Express Static File Serving

In production, Express serves the compiled React build as static files.
The backend/app.js contains:

  if (process.env.NODE_ENV === 'production') {
    app.use(express.static(path.join(__dirname, '../build')));
    app.get('*', (req, res) => {
      res.sendFile(path.join(__dirname, '../build', 'index.html'));
    });
  }

This ensures React Router's client-side routes work correctly when users
navigate directly to URLs like /destinations/5 or refresh the page.

4.3 Environment-Driven API URL

The frontend API base URL is controlled entirely by environment variable:

  // src/services/api.js
  const API_BASE_URL = process.env.REACT_APP_API_URL || 'http://localhost:5000/api';

In production on Render, REACT_APP_API_URL is set before npm run build runs,
embedding the production URL into the compiled JavaScript bundle.

6. CLOUD DATABASE SETUP
================================================================================

6.1 RATIONALE FOR CLOUD MYSQL

Render's Web Service instances are ephemeral — they do not have persistent local
storage. A local MySQL installation cannot be accessed from Render's servers.
A managed cloud MySQL provider is required.

6.2 AIVEN FOR MYSQL (RECOMMENDED)

Aiven provides a free-tier managed MySQL service with:
  - 5 GB storage
  - Automated daily backups
  - TLS/SSL encryption in transit
  - Connection pooling
  - Monitoring dashboard

Connection credentials provided after provisioning:
  Host:     mysql-xxxxxxxx.aivencloud.com
  Port:     12345
  User:     avnadmin
  Password: [generated]
  Database: defaultdb
  SSL Mode: REQUIRED

6.3 DATABASE MIGRATION IN PRODUCTION

The backend/database/migrate.js script creates all tables if they do not exist.
This is run as a one-time step during the first deployment:

  node database/migrate.js

Tables created by migration:
  - users (id, name, email, password_hash, role, created_at)
  - categories (id, name, description)
  - destinations (id, name, description, state, category_id, best_time_to_visit)
  - hotels (id, name, destination_id, price_range, star_rating, description)
  - reviews (id, destination_id, user_id, rating, comment, created_at)

6.4 SEED DATA

An optional seed script (backend/database/seed.js) populates the database with
sample Indian travel destinations, categories, and hotels for demonstration.

10. SECURITY HARDENING FOR PRODUCTION
================================================================================

10.1 SECURITY MEASURES IMPLEMENTED

Category              | Measure                  | Implementation
----------------------|--------------------------|----------------------------
Authentication        | JWT stateless auth       | jsonwebtoken + bcryptjs
Password Security     | bcrypt hashing (12 salt) | bcryptjs
HTTP Headers          | Security headers         | Helmet.js
Input Validation      | Request validation       | express-validator
SQL Injection         | Parameterised queries    | mysql2 prepared statements
CORS                  | Whitelist origins        | cors + env-var allowedOrigins
Rate Limiting         | (Future enhancement)     | express-rate-limit ready
XSS Prevention        | CSP headers              | Helmet.js
Sensitive Data Logs   | Data masking in logs     | logger.js maskSensitiveData()
Secrets Management    | Env vars only            | dotenv + Render env vars

10.2 HELMET.JS HTTP SECURITY HEADERS

In production, the following headers are set automatically:

  X-Content-Type-Options: nosniff
  X-Frame-Options: SAMEORIGIN
  X-XSS-Protection: 0 (deprecated; CSP used instead)
  Strict-Transport-Security: max-age=15552000; includeSubDomains
  Content-Security-Policy: [configured]
  Referrer-Policy: no-referrer

10.3 JWT SECURITY CONFIGURATION

  Algorithm:   HS256 (HMAC-SHA256)
  Expiry:      7 days (configurable via JWT_EXPIRES_IN)
  Secret:      64-char random hex (Render auto-generated)
  Storage:     localStorage (with 401 auto-redirect on expiry)
  Rotation:    Quarterly or on suspected compromise

15. CHALLENGES AND RESOLUTIONS
================================================================================

Challenge 1: CORS Errors in Production
  Cause:    CORS_ORIGIN env var not set to Render's assigned URL
  Solution: Implemented whitelist-based CORS with comma-separated origins.
            Updated after first deploy with correct Render URL.

Challenge 2: React Router 404 on Page Refresh
  Cause:    Browser requests /destinations/5 directly; Express returns 404
  Solution: Added catch-all route in app.js serving index.html for all
            non-API routes in production mode.

Challenge 3: Cloud MySQL SSL Requirement
  Cause:    Aiven requires SSL/TLS; default mysql2 config uses no SSL
  Solution: Added ssl: { rejectUnauthorized: false } to database config
            when DATABASE_URL or NODE_ENV=production is detected.

Challenge 4: REACT_APP_ Variables Not Available in Production
  Cause:    REACT_APP_* vars are embedded at build time, not runtime
  Solution: Added REACT_APP_API_URL to Render environment vars so it is
            available BEFORE npm run build executes.

Challenge 5: Render Free Tier Sleep
  Cause:    Render spins down free services after 15 min inactivity
  Solution: Configured UptimeRobot to ping the health check endpoint
            every 5 minutes, keeping the service warm.

Challenge 6: JWT Secret Inconsistency
  Cause:    JWT_SECRET missing from Render env vars on first deploy
  Solution: Documented in Render env var setup guide. Used Render's
            "Generate" button for cryptographically secure value.

APPENDIX B: DEPLOYMENT TROUBLESHOOTING GUIDE
================================================================================

Error: "Access denied for user"
  Cause:   Wrong DB_USER or DB_PASSWORD
  Fix:     Verify credentials in Render env vars match cloud DB

Error: "CORS policy blocked"
  Cause:   CORS_ORIGIN doesn't match browser's origin header
  Fix:     Set CORS_ORIGIN to exact Render URL (no trailing slash)

Error: "Cannot GET /destinations"
  Cause:   React build not found or catch-all route missing
  Fix:     Ensure build runs BEFORE backend install in buildCommand

Error: "JWT malformed" or "invalid signature"
  Cause:   JWT_SECRET changed between token issue and verification
  Fix:     Set JWT_SECRET in Render env vars; clear browser localStorage

Error: App sleeping / 30-second cold start
  Cause:   Render free tier spins down after inactivity
  Fix:     UptimeRobot ping every 5 minutes at /

  Cause:   Express not serving index.html for client-side routes
